# CoopConnect

منصة ويب لإدارة التدريب التعاوني تربط الطلاب بجهات التدريب، وتنظّم خطة التدريب والتقارير في مكان واحد.

| الطبقة | التقنية |
| --- | --- |
| Front-end | Next.js 16 (App Router) + React 19 + Tailwind CSS 4، واجهة عربية RTL |
| Back-end | Node.js 22 + Express 5، REST API، JWT + RBAC، تحقق المدخلات بـ zod |
| Database | PostgreSQL 16 + Prisma ORM |
| Deployment | Docker + docker-compose |

## ما الذي يعمل الآن

### الواجهة
- **صفحة تعريفية كاملة (Landing):** المزايا، الخطة، الأدوار، خطوات العمل، أمثلة تخصصات ومجالات، رؤية 2030، الأسئلة الشائعة.
- **نظام تصميم موحّد:** خط IBM Plex Sans Arabic، وهوية بتدرجات الأزرق برموز ألوان للوضعين النهاري والليلي (`--brand` في `globals.css`، والنص الأبيض عليه يحقق تباين WCAG AA في الوضعين)، ومكونات أساسية مشتركة. يبقى الأخضر للحالات الناجحة فقط (معتمد، مقبول).
- **لوحة تحكم بقائمة جانبية مجمّعة** (الرئيسية، التدريب، الحساب) وشريط علوي يعرض عنوان الصفحة ووصفها، وتتحول القائمة إلى درج على الجوال.
- **رسائل الأخطاء بالعربية**، ورسالة واضحة عند تعذّر الاتصال بالخادم.

### خطة التدريب (مفتوحة لأي تخصص ومجال)
- **لا قوائم مغلقة:** يكتب الطالب تخصصه والمجال الذي سيتدرب فيه فعلاً بكلماته، حتى لو كان غير معتاد لتخصصه (مثل: علوم الحاسب ← الدعم الفني في مستشفى). تظهر اقتراحات مجالات حسب التخصص المكتوب، واقتراحات لبيئة التدريب (مستشفى، بنك، جهة حكومية...)، وكلها اختيارية (`backend/src/lib/plans/fields.js`).
- **طريقتان للبدء:** «مسودة جاهزة أعدّلها» أو «خطة فارغة أبنيها بنفسي».
  - **المحرك المدمج** يبني مسودة لأي مجال من 4 إلى 52 أسبوعاً على 5 مراحل، بمهام عامة تناسب أي جهة؛ وإذا طابق المجال أحد المسارات التفصيلية في `catalog.js` استخدم أدواته ومهامه الأدق.
  - عدد المهام يتبع ساعات العمل: مهمة لكل 10 ساعات تقريباً (من 2 إلى 5 أسبوعياً) إضافة إلى التقرير الأسبوعي. مهام التهيئة والتسليم تظهر مرة واحدة، وخطوات المشروع تتقدم أسبوعاً بعد أسبوع ولا ترجع للخلف، ويكمل العمل المتكرر (مثل مراجعة الأسبوع مع المشرف الميداني) ما تبقى من الأسبوع.
  - **المساعد الذكي (Claude):** عند ضبط `ANTHROPIC_API_KEY` يكيّف المسودة مع المجال والبيئة والجهة وأهداف الطالب ومهاراته. المخرجات مقيّدة بمخطط JSON وتُتحقق بنيتها؛ وإن فشل أي شيء تُحفظ مسودة المحرك.
- **مساحة عمل واحدة للخطة:** قائمة الأسابيع على الجانب، والأسبوع المختار يُعدَّل في مكانه: العنوان والمرحلة والمهام (مع نوعها: تدريب ميداني أو تعلّم ذاتي) والأهداف والمخرَج والمهارات والمعلَم. إضافة الأسابيع ونسخها وحذفها وإعادة ترتيبها. **حفظ تلقائي** مع مؤشر حالة الحفظ، والحفظات تُنفَّذ بالترتيب فلا تطغى نسخة قديمة على أحدث.
- **ماذا استفدت هذا الأسبوع؟** عند انتهاء أي أسبوع (اكتملت مهامه، أو مضى أسبوعه حسب تاريخ البدء) يُطلب من الطالب أن يكتب ما استفاده: بطاقة في النظرة العامة لأحدث أسبوع منتهٍ لم يُكتب عنه، وحقل في صفحة كل أسبوع، ونقطة تنبيه في قائمة الأسابيع. يُحفظ داخل الأسبوع في الخطة (`PUT /api/plans/:id/weeks/:weekNo/reflection`، من 10 إلى 2000 حرف) ويبقى مع تعديل الخطة وإنجاز المهام.
- تبقى الخطط السابقة محفوظة ويمكن اعتماد أي منها أو حذفها.

### بقية المنصة

- **المصادقة والأدوار:** صفحتا تسجيل دخول وإنشاء حساب بتصميم جديد (التخصص نص حر مع اقتراحات، والجامعة من قائمة جامعات المملكة، والدرجة العلمية دبلوم أو بكالوريوس وهي مطلوبة، والمعدل من 4 أو من 5). الأدوار الفعّالة ثلاثة: طالب، وجهة تدريب معتمدة، ومسؤول النظام.
- **أمان الجلسة:** رمز الدخول (JWT) يُحفظ في كوكي `httpOnly` لا تستطيع سكربتات الصفحة قراءته، ويُرسل لمسارات `/api` فقط (`SameSite=Lax`، و`Secure` في الإنتاج). أي طلب يعدّل البيانات يُرفض إن لم يأتِ من أصل الواجهة المسموح (`CORS_ORIGIN`) حمايةً من CSRF. كلمات المرور مخزّنة كبصمة bcrypt بمعامل 12، ولا تُحفظ كما هي.
- **سياسة كلمات المرور** (`backend/src/lib/password.js`، تُطبق على كل كلمة مرور جديدة أو معدّلة): 10 أحرف على الأقل وحتى 72 بايت (حد bcrypt)، تجمع أحرفاً وأرقاماً، ليست من الكلمات الشائعة ولا حرفاً مكرراً، ولا تحتوي اسم صاحب الحساب أو بريده. الحسابات القائمة تستمر بالدخول بكلماتها الحالية. تعرض صفحة التسجيل قائمة تحقق فورية، وتظهر رسائل الرفض بالعربية.
- **دور المشرف الأكاديمي معطّل مؤقتاً:** حسابات المشرفين لا تستطيع الدخول (ولا استخدام جلسة قائمة)، ولا يمكن إنشاؤها أو إسنادها، ويراجع مسؤول النظام التقارير بدلاً منه. يُعاد تفعيله بضبط `SUPERVISOR_ROLE_ENABLED=true` في الخادم و`NEXT_PUBLIC_SUPERVISOR_ROLE_ENABLED=true` في الواجهة.
- **الوضع النهاري والليلي:** النهاري افتراضياً، مع زر للتبديل يتذكر اختيار المستخدم.
- **دليل جهات التدريب:** يتصفح الطالب الجهات المعتمدة التي فتحت التدريب التعاوني، ويبحث فيها حسب الاسم والمدينة والتخصص، ثم يفتح «تفاصيل الجهة» ليرى النبذة والتخصصات والموقع على الخريطة والموقع الإلكتروني والبريد، ويتواصل معها مباشرة. تعدّل الجهة ملفها بنفسها، ويضيف المسؤول جهات لم تسجّل في المنصة ويعدّلها.
  - **الشعارات:** لكل جهة شعارها. يرفعه المسؤول أو الجهة نفسها (PNG/JPEG/WebP حتى 300 كيلوبايت؛ يُتحقق من النوع من محتوى الملف، ولا يُقبل SVG)، ويُخزَّن في قاعدة البيانات ويُقدَّم من الخادم لا من مواقع خارجية، ولا يظهر إلا للجهات المعتمدة. شعارات الجهات الأولية في `backend/prisma/logos/` مع مصادرها في `SOURCES.md`.
  - **منصات التدريب المعتمدة:** يضم الدليل منصات التدريب المعروفة في المملكة التي يستفيد منها الطالب في التعلّم الذاتي والشهادات، وتحمل علامة الاعتماد: منصة دروب (هدف)، ومؤسسة مسك، ومنصة إثرائي (معهد الإدارة العامة)، ومنصة إدراك، وأكاديمية منشآت، وأكاديمية طويق، ومنصة سطر. روابطها الرسمية تم التحقق منها في نوفمبر 2026 (`TRAINING_PLATFORMS` في `backend/prisma/companies.js`)، وتمر بيانات الجهات الأولية كلها باختبار يطبق عليها نفس تحقق مدخلات المسؤول.
  - البيانات الأولية جهات حقيقية لديها برامج تدريب تعاوني معلنة، مرتبطة بصفحاتها الرسمية (`backend/prisma/companies.js`، تم التحقق منها في أكتوبر 2026). شروط القبول ومواعيده تتغير كل دورة، لذا يحدّثها المسؤول من لوحته.
- **الفرص:** إضافة إلى التواصل المباشر، تنشر الجهة المعتمدة فرصاً على المنصة، وتغلقها وتعيد فتحها، ويقدّم الطالب عليها من تفاصيل الجهة.
- **الطلبات:** تقديم الطالب، سحب الطلب، قبول/رفض الجهة مع التحقق من المقاعد، وإنشاء حالة تدريب (Placement) تلقائياً عند القبول.
- **لوحة المسؤول (تحكم كامل):**
  - **المستخدمون:** كل الحسابات (طلاب، جهات، مسؤولون) مع البحث والتصفية حسب الدور وأحدث التسجيلات. لكل حساب صفحة تفاصيل لتعديل الاسم والبريد وبيانات الطالب، وتعيين كلمة مرور جديدة، وإيقاف الحساب أو حذفه، والاطلاع على خطط الطالب وطلباته وتدريبه. الحساب الموقوف لا يستطيع الدخول ولا استخدام جلسته الحالية. يضيف المسؤول مسؤولين آخرين.
  - **طلبات تسجيل الجهات:** تسجّل الجهة بستة حقول فقط (اسم مسؤول التدريب، البريد، كلمة المرور، اسم الجهة، المدينة، القطاع)، فيصل طلبها إلى لوحة المسؤول مع عدّاد على القائمة الجانبية. يمر الطلب بالحالات: جديد ← تم التواصل ← معتمد أو مرفوض. في نافذة الطلب: بيانات مسؤول التدريب وزر مراسلته بالبريد، وقائمة بما يُستكمل قبل الاعتماد (السجل التجاري، النبذة، طريقة التقديم، التخصصات) مع استكمالها، وسجل تواصل داخلي بالملاحظات لا تراه الجهة. حقل الاعتماد يتبع حالة الطلب فقط، ولا يمكن تعديله من مكان آخر. ترى الجهة مراحل طلبها في لوحتها حتى يُعتمد.
  - **علامة الاعتماد:** منفصلة عن قبول الطلب (القبول يحدد ظهور الجهة للطلاب، والعلامة شارة «جهة معتمدة» بجانب اسمها). الجهات التي تسجّل بنفسها تحملها تلقائياً، والجهات التي يضيفها المسؤول بلا علامة حتى يمنحها إياها من لوحته. لا تُضبط إلا من `PATCH /api/admin/companies/:id/accreditation`، وتُرفض في أي طلب آخر، ويُسجَّل كل تغيير في سجل الجهة الداخلي. يستطيع الطالب تصفية الدليل بالجهات المعتمدة فقط.
  - **جهات التدريب:** قبول الجهات المسجلة، وإضافة أي جهة وتعديلها وحذفها ورفع شعارها، وإخفاؤها عن الطلاب أو إظهارها.
  - **الفرص والطلبات:** كل الفرص المنشورة، ونشر فرصة لأي جهة، وإغلاقها أو حذفها، ومتابعة كل الطلبات.
  - **حالات التدريب:** تغيير الحالة، وحذف التدريب، ومراجعة التقارير واعتمادها أو إعادتها، وتسجيل تدريب لطالب قُبل بالتواصل المباشر مع الجهة.
- **التقارير:** تقارير أسبوعية ونهائية يراجعها مسؤول النظام (اعتماد أو إعادة بملاحظات)، وتعديل الطالب للتقرير المُعاد. في صفحة الطالب: عدادات (المرفوعة، المعتمدة، المُعادة، الأسابيع بلا تقرير)، وزر «استيراد مهام الأسبوع من خطتي»، و**دليل كتابة التقارير وتنظيم التدريب** (هيكل التقرير، مثال ضعيف مقابل قوي، أقسام التقرير النهائي، تنظيم الوقت، نصائح، أخطاء شائعة).
- **الدعم الفني (التذاكر):** يفتح الطالب أو الجهة تذكرة (مشكلة تقنية، استفسار أو شرح، أخرى) ويرد عليها مسؤول النظام في نفس المحادثة، مع عدّاد للتذاكر المنتظرة على القائمة الجانبية. الحالات: بانتظار الرد ← تم الرد ← مغلقة، ورد المستخدم يعيدها إلى قائمة المسؤول. لا يرى المستخدم إلا تذاكره (تذكرة غيره تُعامل كأنها غير موجودة)، ولا يظهر له اسم المسؤول الذي رد. الحماية: حد أقصى 5 تذاكر مفتوحة لكل حساب و200 رسالة لكل تذكرة، وتحديد معدل الكتابة لكل حساب، وتحقق من الطول والحقول (تُرفض أي حقول إضافية)، والنص يُعرض نصاً لا HTML.
- **لوحة الطالب:** نظرة عامة بخطوات رحلة التدريب التعاوني (الخطوة التالية بارزة)، ومهام الأسبوع الحالي، ومؤشرات التقدم.
- **إنهاء التدريب:** يتطلب تقريراً نهائياً معتمداً.

**لم يُنفّذ بعد:** رفع الملفات (السيرة الذاتية والمرفقات)، نماذج التقييم (Rubrics)، شهادات PDF برمز QR، الإشعارات بالبريد، والمراسلة الداخلية.

## التشغيل بـ Docker

```bash
docker compose up --build
docker compose exec api npm run db:seed   # بيانات تجريبية (اختياري)
```

الواجهة: http://localhost:3000 — الـ API: http://localhost:4000/api

## التشغيل المحلي للتطوير

المتطلبات: Node.js 22 وPostgreSQL 16.

```bash
# 1) قاعدة البيانات
createdb coopconnect   # أو عبر psql، ثم عدّل DATABASE_URL في backend/.env

# 2) الخادم
cd backend
cp .env.example .env
npm install
npx prisma migrate dev
npm run db:seed
npm run dev            # http://localhost:4000

# 3) الواجهة (في نافذة أخرى)
cd frontend
cp .env.example .env.local
npm install
npm run dev            # http://localhost:3000
```

### حسابات تجريبية (كلمة المرور لجميعها: `Password123`)

> هذه الحسابات تنشئها `npm run db:seed` مباشرة في قاعدة البيانات للتطوير فقط، لذا لا تمر بسياسة كلمات المرور. لا تستخدمها في الإنتاج.

| الدور | البريد |
| --- | --- |
| مسؤول النظام | admin@coopconnect.sa |
| طالب | student@coopconnect.sa |
| جهة تدريب (معتمدة، حساب عرض) | company@coopconnect.sa |

## الاختبارات

اختبارات تكامل للـ API (Jest + Supertest) تعمل على قاعدة بيانات منفصلة:

```bash
cd backend
createdb coopconnect_test
DATABASE_URL=postgresql://coop:coop@localhost:5432/coopconnect_test npx prisma migrate deploy
DATABASE_URL=postgresql://coop:coop@localhost:5432/coopconnect_test JWT_SECRET=test NODE_ENV=test npm test
```

> تحذير: الاختبارات تفرّغ جداول قاعدة البيانات المستخدمة، فلا تشغّلها على قاعدة التطوير.
